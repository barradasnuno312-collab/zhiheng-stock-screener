# 产品判断

知衡面向有投资基础的普通投资者，服务收盘后或周末的选股研究：用户有一个方向，却不一定知道“经营改善”“估值不贵”“走势稳定”应该如何成为具体指标与阈值。

核心价值是让条件可控、解释可核查、修改可比较。AI负责把研究意图说清楚，用户保留指标及阈值的决定权。

## 演示主任务

输入“在沪深300中，找经营改善、估值不要太贵、最近走势相对稳定的公司”。

模型建议以累计营收同比为正且增速提高作为“经营改善”的代理，用正PE上限表达“不太贵”，用60日年化历史波动率上限表达“稳定”。每个代理都有明确限制；用户点击“筛选 N 条条件”时确认当前指标和阈值。系统不声称这些代理完整代表企业经营、合理价值或未来风险。

筛选后先查看入选与排除原因，需要时再展开指标定义、计算方式、原始输入和来源。修改一个波动率阈值，可在同一快照中观察新增、移出及变为待核实。结果可按当前分类导出CSV，条件可生成不含访问码和历史名单的分享链接。随后保存新版本，查看真实保留数据下的历史变化并建立跟踪。结果为零时保留真实结果，提供“只差一条”与排除原因帮助调整。

## 交互原则

- 主路径为“描述想法 → 生成或编辑条件 → 筛选 → 查看原因”，不再要求额外勾选确认框；主按钮文案明确本次生效条件数，并作为确认动作。
- 指标含义、数据口径和计算方式默认折叠；个股页先呈现本次使用的指标，其他指标及原始接口信息继续按需展开。
- 普通用户优先看到“原因、数据日期、历史变化”等任务语言；专业用户仍可复核报告期、披露日、公式版本、原始字段和请求来源。
- 快速开始、状态定义、操作差异、常见问题和反馈渠道统一放入按需打开的帮助入口；主界面不重复陈述相同规则。详细审计见[用户体验内容评估](ux-content-audit.md)。

## 范围取舍

- 完整沪深300优先于泛称全A股；明确记录当前成员版本。
- 10项有确定口径的指标优先于大量无法追溯的因子；新增20日收益和均线距离仍从已验证连续日线复算。
- 透明AND条件优先于不可解释的综合打分；行业百分位与OR不静默改写。
- 保存、分享、导出、历史快照复盘和条件监控构成完整延续流程；复盘不以不可靠的历史成分和时点数据拼凑收益回测。
- 没有真实数据时明确等待；模型不可用时可手动编辑；接口错误不解释为正常零结果。
- 不采用装饰性图片，让条件、数值、单位、日期和来源成为主要界面信息。

## 验证目标

陌生评审应能在3分钟内完成一次筛选、调整一个阈值并解释一条排除原因。这是待验证目标，不是已测得的用户研究成果。

验收看主流程完成率、显式阈值保留、解释可追溯、修改影响可理解与异常透明；不以收益率或未来涨跌作为产品效果证明。当前尚未完成用户走查。
