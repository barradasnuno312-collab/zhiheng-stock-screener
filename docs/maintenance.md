# 运行与维护

## 访问和数据

公开入口使用统一评审访问码建立独立访客会话。策略归属于当前访客Cookie；换浏览器、清除Cookie或退出后重新进入，会建立新访客身份，不自动找回旧策略。公开访问码和独立管理凭证不能互相替代。

页面筛选、改阈值、比较和恢复都使用持久化快照，不会为每次操作重复拉取300只股票。完整快照的价格日期、抓取时间、财报披露日含义不同，评审时以页面标注为准。

扶摇Key、评审访问码和管理凭证只写服务端私有环境变量。`.env.example`仅列变量名，不能直接作为可用凭证。更新online环境变量后按平台说明重新发布，确认新配置生效。

## 自动运行

3个自动化名称必须与`research.automation.ts`中的绑定一致：

- `zhResearchJob`：`zh_jobs`表INSERT后处理一个有界任务；后续分片继续入队。
- `zhDailyMonitor`：每天北京时间16:30创建全局刷新；休市日只记录无新交易日，交易日生成快照后检查所有启用策略。
- `zhRecovery`：每30分钟恢复一个遗留或租约过期的任务。

修改或启用触发器后须重新发布，旧INSERT不会自动重放。可用CLI实际帮助查看配置命令；平台版本存在差异时以当前`--help`为准。

```bash
lark-cli apps +automation-list --app-id <app_id> --as user
lark-cli apps +log-list --app-id <app_id> --keyword daily-monitor-trigger --since 1d --as user
lark-cli apps +log-list --app-id <app_id> --keyword recovery-trigger --since 1h --as user
```

`daily-monitor-trigger`日志只证明调度进入处理函数；还需检查监控事件中`source=schedule`与终态。只有任务ID或手动“立即检查”不能作为自动调度证据。

## 故障定位

| 页面或任务表现 | 检查与处理 |
| --- | --- |
| AI解析失败或额度耗尽 | 保留原话和明确提示，使用手动条件编辑；不替换为假解析 |
| 刷新停留在等待/执行中 | 管理入口查看root任务状态，再查INSERT与恢复cron；不要重复创建整池任务 |
| 数据源拒绝访问 | 检查Key权限和实际业务code；权限错误不反复重试 |
| 个股指标待核实 | 打开证据查看缺值、停牌、负估值或财务不可比原因；不将它们改成0 |
| 监控无变化 | 核对检查来源、行情日和数据版本；休市无变化是正常终态 |
| 构建期间本地502 | 生产构建与watch服务共用编译目录；串行执行构建和接口验收 |

维护接口`POST /api/maintenance/recover`只接受独立管理凭证，恢复一个待处理单元；后续仍依赖INSERT触发器。逐任务`development/work`接口在线上返回404。恢复操作不删除或覆盖已保存策略。

管理刷新每小时最多一次，单访客模型解析每天10次、全应用每天100次；普通条件编辑和比较不消耗模型额度。仅使用已有额度，额度不足时停止自动扩大调用。

## 发布与来源核对

先提交并推送到应用`sprint/default`，再创建release；`release-get`返回finished后核对`commit_id`。公开源码副本附来源提交及逐文件SHA-256，发布清单记录release与应用URL。不要把本地已修改但未推送的文件视为线上版本。

原始行情缓存、会话、访问码、日志和平台私有配置保留在私有环境，不进入公开源码或录屏。公开评审只需要应用URL、评审访问码和作品源码URL。
