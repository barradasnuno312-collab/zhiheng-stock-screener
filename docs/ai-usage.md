# AI使用与验证记录

本作品使用AI编码助手辅助产品拆解、TypeScript实现、样例设计和检查；交付材料如实区分“已编写”“测试通过”和“尚待真实验证”。不把自动生成代码视为天然正确。

## 运行时AI

- 官方插件 `@official-plugins/ai-text-to-json@1.0.26`，实例 `zh-intent-parser`，动作 `textToJson`，unary输出。
- 固定模型ID `2015`来自插件manifest；未核实其品牌名称，不擅自映射。
- 输入只有文本：用户原话、指标目录JSON字符串、已有条件JSON字符串。
- 输出为意图摘要、条件、最多2条澄清、未支持项与警告；后端再次校验白名单、单位、窗口与范围。
- 15秒解析超时，任务持久化后返回可查询终态；失败允许手动条件编辑，不伪造实时AI结果。
- 每访客每日10次、全应用每日100次；普通条件修改和比较不调用模型。
- 模型不输出实际股票事实、不运行任意SQL/JS、不作收益承诺或直接买卖指令。

## 实际验证

2026-10-02首次真实请求“找市盈率小于30倍的沪深300股票”成功，约7.2秒完成后台执行并可通过任务接口读取结果；阈值30及lt操作符正确保留。

随后13组真实输入通过既定预期：明确PE、中文数字、营收增长“一成”、亿元换算、波动率边界、经营改善代理、模糊估值与稳定、增量修改、删除条件、硬冲突、行业百分位、确定性预测/买卖承诺、OR组合。检查依据是返回的结构化字段，不只看“请求成功”。

这些用例只验证当前代表性表达，不能推出任意自然语言都能正确理解。用户点击主筛选按钮时确认当前条件，服务端仍要求`confirmed=true`，并由确定性校验拦截非法执行。

## 实际发现与修正

| 问题 | 处理与证据 |
| --- | --- |
| 插件CLI子命令与文档示例不一致 | 使用仓库hydrate脚本获得实际action、schema与输出模式，再真实调用验证 |
| 框架默认开发HTTP日志可记录headers | 扶摇适配器使用独立HttpModule；接入真实Key后扫描开发日志与100条线上日志样本，未命中访问码、管理凭证或扶摇Key。样本检查不能推为全部历史日志保证 |
| 原始0与缺失、负PE等容易被误判 | 以合成可复算测试确认三态与不适用规则 |
| 取数任务中断可造成重复请求或漏成员 | 持久化父任务下一分片、确定性子任务/事实ID、租约与平台恢复触发器；云端真实恢复cron接续遗漏任务后完成300成员，刷新运行中重复请求返回同一任务。未执行强杀进程故障注入 |
| 生产构建与开发验收共用编译目录 | 实测watch服务短暂重启、接口502；保留中断记录，服务恢复后仅重跑未通过项。未将这次中断记作模型语义错误 |
| 页面刷新时已完成解析草稿未恢复 | 增加完成任务恢复分支；类型检查通过；云端自动解析后的两条条件已在Chrome展示 |
| 财务指标真实字段名与文档有差异 | 读取真实响应后按实际字段交叉核验；12项同比复算通过，生产计算仍基于利润表原始字段 |
| JSONB重排字段导致条件误判为修改 | 线上恢复测试先发现字符串比较误报，Chrome进一步发现保存按钮受同类逻辑影响；改用逐字段值比较，31项算法及回归测试通过 |

## 验证范围

完整300成员、37项线上流程、3股共12项产品数值复算均通过。云端INSERT自动解析、恢复cron及公开匿名访客入口已验证。修复后的桌面Chrome已完成改单条件、保存、监控和恢复，另有2项线上比较回归通过。

每日监控真实cron于2026-10-02 22:05触发，并生成`source=schedule`、`status=closed`的休市记录；随后恢复每日16:30配置。移动设备模拟已核对工作台、结果表和策略监控页布局，个股证据弹窗的移动交互受浏览器桥接超时限制，详见测试报告。没有进行真实投资者访谈、交易日跨日观察或收益验证。

2026-10-03指标目录扩展至10项。意图插件继续接收服务器实时指标目录，不硬编码新增metricId；本轮没有重复消耗真实模型额度进行语义回归。新增20日收益和均线距离由确定性程序计算，历史快照复盘也不调用模型、不生成收益结论。
